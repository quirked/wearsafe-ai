# D03 smoke test — PPG-DaLiA features + wrist-PPG vs ECG reliability (S03, S06)

Date: 2026-10-12. Scope (user-approved): smoke test only, on PPGDALIA_S03 (normal) and PPGDALIA_S06 (shortened). Inputs are the D02 v1 outputs: `normalized_signals_v1`, and `windows_v1` with the windowing-v2 roles. The full 15-subject D03 run has NOT been started.

All numbers come from `reports/D03_ppg_dalia_smoke_v1_tables.md` (section numbers in brackets), generated by `scripts/d03_report.py` from:
- the feature tables;
- `results/2026-10-12_D03_bvp_hr_vs_ecg_smoke_v1/`.

## Plain-language summary

1. **The features were computed for every window, and all automatic checks passed.** That is 45 of 45 checks [§1]:
   - 13,989 motion windows (2 s), 5,594 context windows (5 s) and 930 physiology windows (30 s);
   - one feature row per D02 window;
   - no missing motion features;
   - no forbidden (label-derived or ECG) column among the features [§1, §2].
2. **No peeking into the future.**
   - Each feature only sees the samples inside its own window.
   - The "HR relative to baseline" feature uses only earlier windows.
   - A test confirms this: changing data after a time point never changes features of windows that end before it.
3. **Wrist PPG works when the person is still, and fails when they move.** Wrist HR vs ECG HR, both subjects, every 8 s reference window [§5]:

   | Activity | Average error (MAE) | Within ±10 bpm |
   |---|---|---|
   | sitting | 2.7 bpm | 95% |
   | working | 4.3 bpm | 88% |
   | driving | 5.5 bpm | 85% |
   | lunch | 7.3 bpm | 76% |
   | transient | 11.5 bpm | 69% |
   | walking | 12.1 bpm | 60% |
   | cycling | 20.9 bpm | 63% |
   | table soccer | 25.4 bpm | 29% |
   | stairs | 32.8 bpm | 39% |

   - Errors are mostly **underestimates** (negative bias): during strong movement the wrist sensor misses beats.
   - S06 is much worse than S03 in vigorous activities. On stairs the MAE is 53.2 vs 12.8 bpm, and on table soccer 36.3 vs 13.9 bpm [§5].
4. **The PPG quality score is informative.**
   - The error drops steadily as quality rises: MAE 19.7 bpm at quality 0.5–0.7, against 2.4 bpm at quality ≥ 0.95 [§5].
   - The rank correlation between quality and error size is −0.51 [§5].
5. **The fixed threshold (0.9) is strict.**
   - Only 34% of 8 s windows pass it, with MAE 4.3 bpm on those [§6].
   - In 30 s windows, 86% (S03) and 60% (S06) are marked `physiology_uncertain` [§3, run log].
   - The report-only sensitivity table [§6] shows the trade-off (0.80 keeps 72% with MAE 8.6 bpm). **It was not used to change anything.**
   - The design says that when physiology is uncertain, it is "unknown", not "calm". So a high uncertain rate during movement is the expected, honest outcome.
6. **30 s windows (secondary table) show the same pattern** [§7]:
   - working 2.9, sitting 3.6, driving 4.0 bpm MAE;
   - stairs 29.0, cycling 22.3, table soccer 21.1 bpm.
   - Windows not flagged uncertain are better (sitting 1.0, working 1.0 bpm), but few remain in active periods: 4 stairs windows, no table-soccer windows.
7. **Deterministic.** A separate trial run gave identical feature tables and identical HR-comparison tables [§9].

## Limitations

1. **Label-edge noise lasts longer than the 10 s margin (report-only finding; nothing changed)** [§8].
   - **Method:** motion features were grouped by distance to the nearest activity-label change. If labels were exact, the motion pattern would not depend on that distance.
   - **Result:** it does. Movement variability (median `acc_mag_std`) near the edges, relative to the activity's core (≥ 40 s from an edge):

     | Activity | Ratio to the core | Reaches into |
     |---|---|---|
     | lunch | 7–10× (0–20 s), still 4.4× at 20–40 s | 20–40 s |
     | driving | 2.2–3.1× (0–20 s), 1.6× at 20–40 s | 20–40 s |
     | sitting | 1.9–2.0× (0–10 s), 1.4× (10–20 s), 1.3× (20–40 s) | 20–40 s |
     | working | 2.3× (10–20 s), 1.9× (20–40 s) | 20–40 s |
     | cycling | ~0.5× (calmer than the core) up to 40 s | 40 s |

     For cycling, the start and end of the activity look calmer than its middle.
   - **Meaning:** windows 10–40 s from an edge, which the 10 s rule allows as training candidates, can still contain movement from the neighbouring activity, so their labels are noisy.
   - **Caveats:** this is 2 subjects only, and the edge bins are small (n = 4–80 windows per cell; 4–32 for the 5 s windows).
   - **Status:** per your instruction, the 10 s rule and all v1 training roles are **unchanged**. The table is for information only and will be repeated in the full run.
2. **Wrist PPG during movement is unreliable.**
   - Errors of 20–50 bpm during stairs, table soccer and cycling are typical of wrist PPG motion artefacts.
   - Physiology from these windows must be treated as uncertain.
   - Wrist-HR features must not be read as "calm" during vigorous activity.
3. **High `physiology_uncertain` rate.**
   - With the fixed 0.9 threshold, most active and mixed windows are uncertain.
   - `hr_rel_baseline` is missing in 34% of 30 s windows. Mostly this is because no good-quality window exists in the previous 5 minutes, not only because of the first 300 s [§3].
4. **Two subjects only.** Per-subject differences are large: S06's vigorous-activity errors are 1.4–4.2× those of S03 (cycling 23.65 vs 17.06, table soccer 36.34 vs 13.87, stairs 53.16 vs 12.76 bpm). So these numbers do not generalise until the full run.
5. **Simple BVP pipeline:**
   - 0.5–4 Hz bandpass, Elgendi peaks and median IBI;
   - no motion-artefact removal and no accelerometer-based correction;
   - the stored BVP polarity is used as is.

   All of this was fixed in advance. These results describe this pipeline, not the best possible wrist-HR.
