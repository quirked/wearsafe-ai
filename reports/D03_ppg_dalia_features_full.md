# D03 — PPG-DaLiA features + wrist-PPG vs ECG reliability: full run (15 subjects, v1)

Date: 2026-10-12. Scope (user-approved): full D03 run, with the same code and `config/features_v1.yaml` as the smoke test. Inputs are D02 v1: `normalized_signals_v1`, and `windows_v1` with the windowing-v2 roles.

All numbers come from `reports/D03_ppg_dalia_v1_tables.md` (section numbers in brackets), generated by `scripts/d03_report.py` from:
- the feature tables;
- `results/2026-10-12_D03_bvp_hr_vs_ecg_v1/`.

The per-subject `physiology_uncertain` rates are from the run log `logs/2026-10-12_D03_full.log`. No model has been trained.

## Plain-language summary

1. **All 15 subjects processed; every check passed** (318 of 318) [§1]:
   - 129,474 motion windows (2 s), 51,777 context windows (5 s) and 8,612 physiology windows (30 s);
   - one feature row per D02 window;
   - no missing motion features;
   - no label or ECG columns among the features [§1, §2].
2. **Deterministic.** A separate run produced identical feature tables (3/3) and identical HR-comparison files (13/13) [§9].
3. **Wrist HR vs ECG HR** (every 8 s reference window, 64,697 windows; coverage 99.97%) [§5]:
   - average error across subjects is **10.6 ± 4.8 bpm** (mean ± std over 15 subjects);
   - the watch tends to read low (bias −5.8 ± 6.8 bpm).
4. **Per activity, across subjects** (each subject counted once) [§5]:

   | Activity | MAE mean ± std (bpm) | Within ±10 bpm | Worst subject MAE |
   |---|---|---|---|
   | sitting | 3.5 ± 2.1 | 91% | 8.3 |
   | working | 4.8 ± 2.5 | 86% | 11.1 |
   | driving | 6.6 ± 3.2 | 81% | 13.7 |
   | lunch | 6.9 ± 2.5 | 79% | 12.9 |
   | transient | 11.9 ± 6.2 | 64% | 28.8 |
   | walking | 16.1 ± 10.7 | 52% | 42.7 |
   | table soccer | 16.4 ± 11.3 | 49% | 49.3 |
   | cycling | 21.9 ± 17.6 | 52% | 74.5 |
   | stairs | 28.4 ± 14.7 | 30% | 56.2 |

   - Still activities are accurate; moving ones are not, and they vary a lot between people.
   - During movement the watch mostly *misses* beats, so it under-reads.
5. **Per subject** [§5]:
   - the best subject is S07, with an MAE of 5.8 bpm;
   - the worst is S05 at 23.6 bpm (bias −23.2). S05 is one of the two subjects with a high average HR in D00a;
   - next are S06 (16.5) and S11 (16.4).
6. **The PPG quality score is informative** [§5]:
   - MAE falls from 15.6 bpm (quality 0.5–0.7) to 11.4 (0.8–0.9), 6.4 (0.9–0.95) and 2.2 bpm (≥ 0.95);
   - its rank correlation with error size is −0.42.
7. **Saturation hurts:** windows with any accelerometer saturation have about twice the HR error (17.9–20.3 vs 9.1 bpm) [§5].
8. **The fixed 0.9 threshold is strict** [§6, run log]:
   - it keeps 26% of 8 s windows (MAE 4.0 bpm);
   - 59–100% of each subject's 30 s windows are `physiology_uncertain` (S07 59.3% … S09 99.8%).
   - The **report-only** sensitivity table [§6]: 0.80 keeps 64% (MAE 8.3), 0.85 keeps 43% (6.4), 0.95 keeps 15% (2.2).
   - Nothing was changed.
9. **30 s windows (secondary)** [§7]:
   - the pattern is the same (sitting 4.7, working 5.4, driving 5.9, stairs 25.0, cycling 20.1 bpm);
   - windows not flagged uncertain are accurate when still (sitting 1.1, working 1.5, lunch 1.6, driving 2.3 bpm);
   - but stairs stays poor even when "certain" (27.9 bpm, n = 28). So the quality score does not catch every bad window during stair climbing.

## Limitations

1. **Label-edge noise extends beyond the 10 s margin (report-only; nothing changed)** [§8].
   - **Measure:** motion variability (median `acc_mag_std`, 2 s windows) relative to the same activity ≥ 40 s from any label change, all 15 subjects.

     | Activity | 0–5 s | 5–10 s | 10–20 s | 20–40 s |
     |---|---|---|---|---|
     | lunch | 7.9× | 8.1× | 8.2× | **6.2×** |
     | working | 8.1× | 2.6× | **2.6×** | 1.2× |
     | driving | 2.0× | 2.4× | **2.1×** | **1.6×** |
     | sitting | 3.2× | 2.3× | **1.5×** | 1.2× |
     | cycling | 0.5× | 0.5× | **0.4×** | **0.4×** |
     | walking, stairs, table soccer | within 0.87–1.24× in every bin | | | |

     For cycling, the edges are calmer than the core.
   - **Reading the table:**
     - The protocol labels switch before or after the movement really changes, and for lunch, driving and working this lasts well past 10 s.
     - Windows 10–40 s from an edge are allowed as training candidates by the 10 s rule, and some of them carry the neighbouring activity's movement. That is label noise in context training.
     - The 5 s context windows show the same pattern [§8].
   - **Status:** as instructed, the 10 s rule and all v1 training roles are unchanged.
2. **Wrist PPG is unreliable during movement.**
   - Stairs, cycling, table soccer and walking errors are large and vary widely between subjects.
   - Even "certain" stair windows are poor.
   - Physiology during vigorous movement must be treated as unknown, never as calm.
3. **`hr_rel_baseline` is missing in 50% of 30 s windows** [§3, §2].
   - It is missing in up to 97% for S09 and 87% for S08.
   - Under the fixed 0.9 SQI, many 5-minute histories contain no good-quality window.
   - Only 3.5% of windows are missing it because of the first 300 s.
4. **Simple, fixed BVP pipeline:**
   - 0.5–4 Hz bandpass, Elgendi peaks and median IBI;
   - no motion-artefact removal;
   - stored polarity used as is.

   The results describe this pipeline, not the best achievable wrist HR.
5. **Report wording:** one heading in the generated tables, §5 "Per activity (both subjects pooled)", is a leftover from the smoke test. That table pools all 15 subjects. The script text is now fixed for future runs; the generated file is not edited.

## Findings for later (recorded only; no changes now)

1. **A possible v2 SQI threshold, chosen against ECG agreement on training subjects only.**
   - The fixed 0.9 leaves 59–100% of 30 s windows uncertain and makes `hr_rel_baseline` mostly missing.
   - A v2 threshold could be chosen inside each leave-one-subject-out training fold. The criterion would be the ECG agreement of the training subjects' windows (e.g. the lowest threshold whose MAE ≤ a pre-stated target).
   - It would then be applied unchanged to the held-out subject.
   - The current §6 sensitivity table pools all subjects. It **must not** be used to pick the threshold, because that would use test subjects.
   - This would be a new versioned config (`features_v2`), reported next to v1.
2. **A possible label-edge margin sensitivity experiment: 10 s vs 30 s, reported side by side.**
   - The §8 table suggests noise reaches 20–40 s for lunch, driving, working and sitting.
   - A 30 s margin could be run as a separate windowing config (`windowing_v3`), with the v1 (10 s) results always reported alongside.
   - The margin must be chosen before seeing any model results; this experiment only compares the two pre-stated values.
   - The trade-off is fewer training windows per activity. The cost is visible in the D02 window counts.
